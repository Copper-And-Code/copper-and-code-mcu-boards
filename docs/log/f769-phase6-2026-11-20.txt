== Audio: WM8994 on SAI1 block A, headphone/line output jack CN7
- modules/st_audio/st_audio.c (new): PLLI2S as SAI1 clock (44.1 kHz family N 429 Q 2 DIVQ 19,
  48 kHz family N 344 Q 7 DIVQ 1, then MCKDIV), SAI1_A master TX, 64-bit frame, slots 0 and 2,
  16 bit; DMA2 stream 1 channel 0 (not used by MicroPython on this board) circular over a 32 KB
  ring, no interrupt; what was played is zeroed when the ring is next looked at, so a late feeder
  gives silence. write(buf, mono, shift), queued(), info().
- Pins (ST's .ioc for the board): MCLK PG7, SCK PE5, FS PE4, SD PE6 (AF6); named in pins.csv
  (AUDIO_MCLK, ...), else the port has no pin objects for them.
- python/stm32/audio.py (new): the API of python/esp32/audio.py (beep, tone, play WAV, playing,
  finish, stop) plus volume(); ST's WM8994_Init for headphone out, no input, as register writes;
  a machine.Timer every 20 ms tops the queue up to 8 KB.
- buzzer.py: on an STM32 board with "audio" in stm32_board.CONFIG it uses audio.py; Studio profile
  studio-board.json revision 2 with "buzzer": {"audio": true}.
Checks: codec id 0x8994; DMA 4402 bytes in 50 ms at 22.05 kHz stereo (4410 expected); first sound
380 ms after the call (the codec's start-up sequence, once), then at once.
Owner, headphones on CN7: three beeps, a 440 Hz tone at volume 30/60/90, a melody from a 44.1 kHz
stereo WAV on /sd (1800 ms of sound in 1855 ms): all heard, clean.
With display_driver and an LVGL spinner running: buzzer.beep through the codec, the melody in 1827
ms, 0 underruns, 0 touch errors.
